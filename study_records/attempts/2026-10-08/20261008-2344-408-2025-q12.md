## 题目

在 32 位计算机上执行下列 C 语言代码，则 ui 的真值为：

```c
short si = -32767;
unsigned int ui = si;
```

A. 2^13 - 1  
B. 2^15 + 1  
C. 2^32 - 2^15 - 1  
D. 2^32 - 2^15 + 1

## 用户作答

我操，C++这种问题，这个感觉问的确实是比较底层的。 Short负数转换为 unsigned int是八十。 我理解的话，就是首先关于 short 的储存的话，它应该是有一个符号位，这个符号位的话，应该是用来表示这个负数，它是1嘛。然后接下来你如果直接把这个 unsigned int 给复制这个值，那么它会直接把符号位的这个1当成一个具血值。那么这样一来，我操，我不会我不会，你这教我吧。

## 诊断

用户知道有符号整数的最高位与负数表示有关，但把赋值过程理解为可能直接复制 short 的位模式，并把原符号位当作普通数值位；尚未掌握负整数转换到更宽无符号类型时的标准数值转换规则，也未完成选项判断。

掌握度记为 1：具备补码符号位的初步认识，但核心转换规则缺失，信心明确为低。

## 正确思路

负整数转换为 32 位 unsigned int 时，结果是原数值对 2^32 取模，而不是简单把 16 位模式零扩展：

```text
-32767 mod 2^32
= 2^32 - 32767
= 2^32 - (2^15 - 1)
= 2^32 - 2^15 + 1
```

按常见补码机器理解，16 位 short 的 -32767 位模式为 0x8001；保持其负数含义扩展到 32 位得到 0xFFFF8001，再将该 32 位模式解释为 unsigned int，所得数值与上述模运算一致。
